# Lesson 1.2 · Training vs using a model: build your first one

**Stage 1 · How machines learn** · Build-first · Time: about 60–75 min · **Project P1** continues

## What you'll build today
Your **first real machine-learning model**: a program that *learns* a spam rule from the 5,574 labelled messages
by itself, **saves** it to a file, and a second program that **loads** it and judges new messages.
Then you'll train the same kind of model with **scikit-learn** and check whether it learns the same rule.

**The only theory you need:**
```
TRAINING  (done once, slow)                         INFERENCE  (done many times, fast)
labelled examples ──► try many rules,          new message ──► load the saved model ──► "spam"
                      keep the one with             (no label!)    apply its rule
                      the fewest mistakes
                           │
                           ▼
                   MODEL = a few learned numbers, saved to a file
                   e.g. {"feature": "digits", "threshold": 4}
```
- **Model:** the *learned numbers*, not the data (Lesson 0.1). Today your model is just **two values**: which feature
  to look at, and where to draw the line. Big LLMs are the same idea with billions of numbers.
- **Training:** searching for the numbers that make the **fewest mistakes** on the labelled examples.
- **Inference:** using those numbers on new examples. No labels are needed and nothing is learned.

The model you'll build has a name: a **decision stump**, a one-question rule ("is digits > 4?").

### Step 2: Train: search for the best rule
Create `projects/classifier/train_stump.py`. First, prepare the data:
```python
import json
from pathlib import Path

from sms_data import features, load_sms     # your module from Step 1

labels, texts = load_sms()
rows = [features(t) for t in texts]          # one dict of numbers per message
is_spam = [label == "spam" for label in labels]   # True/False, easier to compare than strings
```
> When you run a script inside `projects/classifier/`, Python looks for imports in **that script's folder**, so
> `from sms_data import ...` works without the `sys.path` trick.

Now a function that **counts the mistakes** of one rule, "spam if `feature_name` > `threshold`":
```python
def mistakes(feature_name, threshold):
    count = 0
    for row, truth in zip(rows, is_spam):
        guess = row[feature_name] > threshold     # True = "I think it's spam"
        if guess != truth:                        # the rule was wrong about this message
            count += 1
    return count
```
<details>
<summary>🔍 Walk-through: how <code>mistakes()</code> works, step by step on 4 messages</summary>

The function answers: *"If I used the rule 'spam if this feature > this number', how many messages would I get wrong?"*

| # | Message | `row["digits"]` | `truth` |
|---|---------|-----------------|---------|
| 1 | "WIN £1000 call 09061701461" | 15 | True (spam) |
| 2 | "See you at 5" | 1 | False (ham) |
| 3 | "Call 07123456789 when you land" | 11 | False (ham) |
| 4 | "FREE entry! Text WIN now" | 0 | True (spam) |

`mistakes("digits", 4)`, the rule "spam if digits > 4":
| # | `guess` = digits > 4 | `truth` | mistake? | `count` |
|---|----------------------|---------|----------|---------|
| 1 | 15 > 4 → True | True | no | 0 |
| 2 | 1 > 4 → False | False | no | 0 |
| 3 | 11 > 4 → True | False | **yes** | 1 |
| 4 | 0 > 4 → False | True | **yes** | 2 |

→ returns **2**. `zip(rows, is_spam)` walks both lists side by side; `row[feature_name]` picks one number from the dict;
`> threshold` already gives True/False. Other lines on the same data: threshold 0 → 3 mistakes, threshold 20 → 2.
**Training = trying many lines and keeping the one with the fewest mistakes.**

Run it yourself:
```python
rows = [{"digits": 15}, {"digits": 1}, {"digits": 11}, {"digits": 0}]
is_spam = [True, False, False, True]

def mistakes(feature_name, threshold):
    count = 0

        guess = row[feature_name] > threshold
        print(f"  {row[feature_name]} > {threshold} -> guess {guess}, truth {truth}")
        if guess != truth:
            count += 1
    return count

for t in [0, 4, 20]:
    print(f"threshold {t}: {mistakes('digits', t)} mistakes")
```

**Try it** before going on. Add `print(mistakes("digits", 4))` and run. Then try a few other thresholds and features
by hand. Which numbers give fewer mistakes? *You are doing training by hand right now.*

Now let the computer do that search for you, over **every feature** and **many thresholds**:
```python
best = None
for name in rows[0]:                                   # every feature name
    values = sorted(set(row[name] for row in rows))    # every different value that feature has
    if len(values) > 100:
        values = values[:: len(values) // 100]         # too many? try about 100 of them (keeps it fast)
    for threshold in values:
        m = mistakes(name, threshold)
        if best is None or m < best["mistakes"]:       # fewer mistakes than the best so far? keep it
            best = {"feature": name, "threshold": threshold, "mistakes": m}
    print(f"tried {name:<25} best so far: {best['feature']} > {best['threshold']} ({best['mistakes']} mistakes)")

accuracy = 1 - best["mistakes"] / len(rows)
print(f"\nModel: spam if {best['feature']} > {best['threshold']}  ->  {best['mistakes']} mistakes, accuracy {accuracy:.1%}")
```
- `set(...)` removes duplicates; `sorted(...)` puts the values in order.
- `values[:: step]` is a **slice** that takes every *step*-th item, so you try about 100 thresholds instead of thousands.
- **Accuracy** = the share of messages the rule got right.

**Run it.** Which feature and threshold won? How many mistakes? Look at the first line too: the best "length" rule makes
**747 mistakes**, which is exactly the number of spam messages. That "rule" is really **"say ham to everything"**,
and it's still **86.6% accurate**. So 86.6% is the score to beat, and any useful model must do better than that.

### Step 4: Inference: use the model on new messages
Create `projects/classifier/predict.py`. It **does not train and does not need labels**. It only loads and applies:
```python
import json
from pathlib import Path

from sms_data import features

model = json.loads(Path("data/models/stump.json").read_text())   # load the learned numbers

new_messages = [
    "WINNER!! You have won a 1000 prize. Call 09061701461 now to claim",
    "Are we still meeting for lunch tomorrow?",
    "Call me at 07123456789 when you land",     # tricky: a normal message, but with a phone number
    "FREE FREE FREE click here",                # tricky: spammy, but no digits
    "",                                          # tricky: an empty message
]
for text in new_messages:
    value = features(text)[model["feature"]]
    guess = "spam" if value > model["threshold"] else "ham"
    print(f"{guess:<5} ({model['feature']}={value})  {text!r}")
```
- `{text!r}` prints the text with quotes, so you can see an empty message as `''`.

**Run it.** Which of the 5 does it get **wrong**, and **why**? (Look at the feature value it printed.)
**Real lesson:** a one-question model is simple and fast, but it only "sees" one number. That's why later models use
**many features at once**.

## ② The package version: scikit-learn (≈15 min)
**scikit-learn** (imported as `sklearn`) is Python's standard library for classic machine learning. A decision stump is
a **decision tree** with only one question, so `max_depth=1`.
```
uv add scikit-learn
```
Create `projects/classifier/sk_stump.py`:
```python
import joblib                                   # saves/loads Python objects (installed with scikit-learn)
from sklearn.tree import DecisionTreeClassifier

from sms_data import features, load_sms

labels, texts = load_sms()
rows = [features(t) for t in texts]
names = list(rows[0])                            # feature names, in a fixed order
X = [[row[n] for n in names] for row in rows]    # a table: one row per message, one column per feature
y = labels                                       # the answers

tree = DecisionTreeClassifier(max_depth=1)       # a one-question tree = a decision stump
tree.fit(X, y)                                   # TRAINING: one line!

print("feature:", names[tree.tree_.feature[0]], "| threshold:", tree.tree_.threshold[0])
print(f"accuracy: {tree.score(X, y):.1%}")

joblib.dump(tree, "data/models/stump.joblib")    # save the model

new = ["Call me at 07123456789 when you land", "Are we still meeting for lunch tomorrow?"]
print(tree.predict([[features(t)[n] for n in names] for t in new]))   # INFERENCE
```
- **`X` and `y`** are the standard names in ML: `X` = the features table, `y` = the labels.
- **`.fit(X, y)`** = train. **`.predict(...)`** = inference. Every scikit-learn model uses these same two methods.
- scikit-learn writes the rule as "digits **<= 4.5** → ham". That's the same line as yours, drawn halfway between 4 and 5.

**Run it.** Same feature? Same line? Same accuracy? Run the same 5 tricky messages through `tree.predict` too.

## 📌 Key takeaways
- A **model** is a small set of **learned numbers**. Yours is 2 values in a JSON file.
- **Training** = searching for the numbers with the fewest mistakes on labelled data. **Inference** = applying them to new data.
- Always compare with the **"always say the common class" baseline** (86.6% here). Accuracy alone can look good when it isn't (Lesson 1.5).
- One feature isn't enough: phone numbers in normal messages fool a digits-only rule.
- scikit-learn's `.fit()` / `.predict()` do the same job in 2 lines, and find the same rule.
