## Idea 1: What an "API call" really is
An **API** (Application Programming Interface) is a door that one program offers to other programs.
Calling the Claude API is like ordering at a counter: you hand over a **filled-in form**, and you get back a
**reply with a receipt**.

```
 YOUR CODE                                              ANTHROPIC'S SERVERS
 ┌─────────────────────────────┐   HTTP POST request   ┌──────────────────────┐
 │ URL:     /v1/messages       │ ────────────────────► │                      │
 │ HEADERS: who I am (API key) │                       │   the model reads    │
 │          which API version  │                       │   your messages and  │
 │          "the body is JSON" │                       │   writes an answer   │
 │ BODY:    model, max_tokens, │                       │                      │
 │          messages           │ ◄──────────────────── │                      │
 └─────────────────────────────┘   HTTP response:      └──────────────────────┘
                                   status code + JSON
                                   (answer + token "receipt")
```

- The **URL** (also called the **endpoint**): the address of the door, `https://api.anthropic.com/v1/messages`.
- **Headers**: small labels on the envelope.
  - `x-api-key`: your API key (proves who you are, so you get billed).
  - `anthropic-version`: which version of the API rules you follow. Use `2026-10-21`.
  - `content-type: application/json`: "the body is written in JSON."
- **Body**: the form itself, written in **JSON** (a text format of keys and values, like a Python dict).
- **Status code**: a number on the reply. `200` = OK. `4xx` = *you* did something wrong. `5xx` = *their* side had a problem.

## Idea 2: The request body
```json
{
  "model": "<the model ID>",
  "max_tokens": 1024,
  "messages": [
    {"role": "user", "content": "Explain what an API is in two sentences."}
  ]
}
```
- `model`: which model answers. The ID comes from Anthropic's "Models overview" docs page.
- `max_tokens`: the **most** tokens the answer may use. It's a safety cap: if the answer hits it, the answer is
  **cut off**. A cap also caps your cost.
- `messages`: the conversation so far. Remember Lesson 0.3: the model is **stateless**, so this list is *everything* it knows.

## Idea 3: The response
Trimmed to the important parts:
```json
{
  "content": [
    {"type": "thinking", "thinking": ""},
    {"type": "text", "text": "An API is a set of rules that lets one program..."}
  ],
  "stop_reason": "end_turn",
  "usage": {"input_tokens": 18, "output_tokens": 142}
}
```
- `content` is a **list of blocks**. Some models **think** before answering. That shows up as a `thinking` block
  (its text may be empty, because the raw thinking isn't shown). **Always pick out the blocks with `type == "text"`**;
  never assume the answer is the first block.
- `stop_reason`: why it stopped. `end_turn` = finished normally. `max_tokens` = **hit your cap, so the answer is cut off**.
- `usage`: the **receipt**. `input_tokens` = how much you sent. `output_tokens` = how much it wrote (thinking included).

## Idea 4: Tokens → money
Prices are given **per million tokens (1M)**, separately for input and output. Output is usually **several times
more expensive** than input. Find your model's prices on Anthropic's pricing page.

```
cost = input_tokens  × (input price  ÷ 1,000,000)
     + output_tokens × (output price ÷ 1,000,000)
```
*Example with made-up prices ($3 in / $15 out per 1M): 18 in, 142 out → 0.000054 + 0.00213 = **$0.0022**.*
Tiny for one call. But an app doing 100,000 calls a day turns "tiny" into a real bill. That's why both roles watch it.

## Idea 5: The SDK
An **SDK** (Software Development Kit) is the provider's **official library** for their API. Instead of building
headers and JSON yourself, you call a Python function. It also handles **retries** (tries again on temporary errors),
gives clear **error types**, and turns the JSON into Python objects.

**Both versions today talk to the same hosted model on Anthropic's servers.** The only difference is *who writes
the HTTP code*: you (①), or the SDK (③). There's no local version ② in this stage; local models come in Stage 10.

### Step 1: ① From scratch with `httpx`: a guided build (≈25 min)
You'll build the script **piece by piece**. After each piece, **run it** and look at what it prints.
Type the code yourself rather than copy-pasting; typing is how your fingers learn it.

#### 1a. Install `httpx`
`httpx` is a Python library for sending HTTP requests: a "browser for your code".
```
uv add httpx
```

#### 1b. Create the file, load `.env`, and set your variables
Create `experiments/00b_hello_raw.py`:
```python
import os                        # gives access to environment variables (os.environ)
import httpx                     # sends the HTTP request
from dotenv import load_dotenv   # reads .env (Lesson 0.4a)

load_dotenv()                    # copies the lines of .env into os.environ

PROMPT = "Explain what an API is in two sentences."   # ← this is your prompt
INPUT_PRICE = 0.0    # $ per 1 million input tokens  (fill in: Claude gives you the numbers in chat)
OUTPUT_PRICE = 0.0   # $ per 1 million output tokens

print("Model:", os.environ["CLAUDE_MODEL"])   # quick check that .env loaded (never print the key!)
```
- `os.environ["CLAUDE_MODEL"]` reads one environment variable. If it's missing you get a `KeyError`: that means
  `.env` didn't load or the name is misspelled.
- **Run it:** `uv run python experiments/00b_hello_raw.py` → it should print `Model: ...`.

#### 1c. Build the headers and the body (Ideas 1 and 2, as Python dicts)
Add below the `print`:
```python
url = "https://api.anthropic.com/v1/messages"

headers = {
    "x-api-key": os.environ["ANTHROPIC_API_KEY"],   # who you are (and who pays)
    "anthropic-version": "2026-10-21",               # which version of the API rules
    "content-type": "application/json",              # "the body is JSON"
}

body = {
    "model": os.environ["CLAUDE_MODEL"],             # which model answers
    "max_tokens": 1024,                              # cap on the answer's length
    "messages": [                                    # the conversation: just one user message
        {"role": "user", "content": PROMPT},
    ],
}
```
These are ordinary Python **dicts** (`{key: value}`). Nothing is sent yet; you've only filled in the form.

#### 1d. Send it and look at the status code
```python
response = httpx.post(url, headers=headers, json=body, timeout=60)
print("Status code:", response.status_code)
```
- `httpx.post(...)` sends a **POST** request (POST = "here's some data, please process it").
- `json=body` turns your dict into JSON text for you.
- `timeout=60` means: give up if there's no reply within 60 seconds (the default is shorter, and an LLM can take a while).
- `response` is the reply. `response.status_code` is the number: `200` = OK.
- **Run it.** You should see `Status code: 200`. If you see something else, check the error table at the bottom.

#### 1e. Stop if it failed
```python
if response.status_code != 200:
    print(response.text)        # the raw reply text: the error message is in here
    raise SystemExit(1)         # stop the script here (1 = "ended with an error")
```

#### 1f. Look at the whole reply once
```python
import json                     # (you can move this import to the top)
data = response.json()          # turn the JSON text into a Python dict
print(json.dumps(data, indent=2))   # print it nicely indented
```
**Run it and read the output slowly.** Find `content`, `stop_reason`, and `usage` (Idea 3). This is exactly what
travels back over the internet. Once you've seen it, delete or comment out the `print(json.dumps(...))` line.

#### 1g. Print only the answer text
`data["content"]` is a **list** of blocks, and each block is a dict with a `"type"`. Loop over them and print only the text ones:
```python
for block in data["content"]:
    if block["type"] == "text":
        print(block["text"])
```

#### 1h. ✋ Your turn: tokens, stop reason, cost
Now write the last part yourself. Use what you saw in 1f:
1. Print `stop_reason`. *Hint:* it's a top-level key: `data["stop_reason"]`.
2. Print the input and output tokens. *Hint:* they're inside another dict: `data["usage"]["input_tokens"]`.
3. Calculate and print the cost with the formula from Idea 4. *Hint:* `1_000_000` is one million (the `_` is just for readability),

### Step 2: ③ With the official SDK: a guided build (≈15 min)
Same job, but the SDK does the HTTP part for you.

#### 2a. Install it
```
uv add anthropic
```

#### 2b. Create `experiments/00b_hello_sdk.py`
```python
import os
import anthropic                 # the official SDK
from dotenv import load_dotenv

load_dotenv()

PROMPT = "Explain what an API is in two sentences."
INPUT_PRICE = 0.0
OUTPUT_PRICE = 0.0

client = anthropic.Anthropic()   # a "client" = an object that talks to the API for you.
                                 # It finds ANTHROPIC_API_KEY in os.environ by itself.
```

#### 2c. Make the call
```python
response = client.messages.create(
    model=os.environ["CLAUDE_MODEL"],
    max_tokens=1024,
    messages=[{"role": "user", "content": PROMPT}],
)
print(response)                  # look at it once, like in 1f
```
Compare this with your raw version:
| Raw `httpx` (Step 1) | SDK (Step 2) |
|----------------------|--------------|
| You write the URL and 3 headers | The SDK adds them for you |
| `"model": ...` inside a `body` dict | `model=...` as a function argument (same names!) |
| You check `status_code` | The SDK **raises an error** (an exception) if something went wrong |
| `data["content"]`: a dict, square brackets | `response.content`: an object, a **dot** |

**Run it** and read what `print(response)` shows. It's the same information as in 1f, just as a Python object.

#### 2d. Print the answer text
```python
for block in response.content:
    if block.type == "text":
        print(block.text)
```
(Same loop as 1g, but with dots instead of `["..."]`.)

#### 2e. ✋ Your turn: tokens, stop reason, cost
Same as 1h, using dots: `response.stop_reason`, `response.usage.input_tokens`, `response.usage.output_tokens`.

#### 2f. Catch errors nicely
When the SDK gets an error from the API, it **raises an exception**, and the script crashes with a long red message
(a "traceback"). To print a short, clear message instead, wrap the call from 2c in `try` / `except`:
```python
try:
    response = client.messages.create(
        model=os.environ["CLAUDE_MODEL"],
        max_tokens=1024,
        messages=[{"role": "user", "content": PROMPT}],
    )
except anthropic.APIStatusError as e:      # any error reply from the API (401, 404, 429, ...)
    print("API error:", e.status_code, e.message)
    raise SystemExit(1)
```
`try:` means "attempt this". `except ... as e:` means "if this kind of error happens, run this instead",
and `e` holds the details.

**Common errors:**
| You see | It means | Fix |
|---------|----------|-----|
| `401` / `authentication_error` | The key is wrong or wasn't loaded | Check the `.env` line name, then `load_dotenv()` before reading it |

| `529` / `overloaded_error` | Their servers are busy | Wait and retry |
| `KeyError: 'ANTHROPIC_API_KEY'` | The environment variable isn't set | `.env` in the repo root? `load_dotenv()` called first? |

**① Full raw `httpx` script (what Step 1 builds):**
```python
import os
import json
import httpx
from dotenv import load_dotenv

load_dotenv()

PROMPT = "Explain what an API is in two sentences."
INPUT_PRICE = 0.0    # $ per 1M input tokens (fill in)
OUTPUT_PRICE = 0.0   # $ per 1M output tokens (fill in)

url = "https://api.anthropic.com/v1/messages"
headers = {
    "x-api-key": os.environ["ANTHROPIC_API_KEY"],
    "anthropic-version": "2026-10-21",
    "content-type": "application/json",
}
body = {
    "model": os.environ["CLAUDE_MODEL"],
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": PROMPT}],
}

response = httpx.post(url, headers=headers, json=body, timeout=60)
print("Status code:", response.status_code)
if response.status_code != 200:
    print(response.text)
    raise SystemExit(1)

data = response.json()
# print(json.dumps(data, indent=2))   # uncomment to see the whole reply

for block in data["content"]:
    if block["type"] == "text":
        print(block["text"])

usage = data["usage"]
cost = usage["input_tokens"] * INPUT_PRICE / 1_000_000 + usage["output_tokens"] * OUTPUT_PRICE / 1_000_000
print("stop_reason:", data["stop_reason"])
print("input tokens:", usage["input_tokens"], "| output tokens:", usage["output_tokens"])
print(f"cost: ${cost:.5f}")
```

**③ Full SDK script (what Step 2 builds):**
```python
import os
import anthropic
from dotenv import load_dotenv

load_dotenv()

PROMPT = "Explain what an API is in two sentences."
INPUT_PRICE = 0.0
OUTPUT_PRICE = 0.0

client = anthropic.Anthropic()
try:
    response = client.messages.create(
        model=os.environ["CLAUDE_MODEL"],
        max_tokens=1024,
        messages=[{"role": "user", "content": PROMPT}],
    )
except anthropic.APIStatusError as e:
    print("API error:", e.status_code, e.message)
    raise SystemExit(1)

for block in response.content:
    if block.type == "text":
        print(block.text)

u = response.usage
cost = u.input_tokens * INPUT_PRICE / 1_000_000 + u.output_tokens * OUTPUT_PRICE / 1_000_000
print("stop_reason:", response.stop_reason)
print("input tokens:", u.input_tokens, "| output tokens:", u.output_tokens)
print(f"cost: ${cost:.5f}")
```

**What you should notice:** the SDK version has no URL, no headers, and no status-code check. It handles those,
**retries** temporary errors (like 429/529) automatically, and raises clear error types (e.g.
`anthropic.AuthenticationError`) instead of you reading status codes. What it **hides**: the URL, the headers, the
version, the retries. When something breaks at a customer (for example their network proxy blocks a header),
knowing the raw request from ① is how you debug it.

**With `max_tokens=50`:** `stop_reason` becomes `max_tokens` and the answer stops mid-sentence. In a real app,
always check `stop_reason`: a cut-off answer shown to a user looks like a bug.

## 📖 New words
| Word | Meaning in one line |
|------|---------------------|
| API | A "door" one program offers so other programs can use it. |
