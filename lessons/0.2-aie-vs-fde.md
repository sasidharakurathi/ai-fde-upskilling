# Lesson 0.2 · What an AI Engineer does vs what a Forward Deployed Engineer does

**Stage 0 · The big map** · Time: about 1 hour (read 20 min · try 25 min · explain back 15 min)

## Why this lesson?
You're learning for two jobs. Before going deeper, you should be able to picture a **normal working day**
in each one. Then you can notice, lesson by lesson, which kind of work you enjoy. That helps you choose
your lean at the role checkpoint after Stage 7.

---

## A story first: the coffee machine company

Imagine a company that makes a very smart coffee machine.

```
            THE FACTORY                                  THE CAFÉS (customers)
   ┌───────────────────────────────┐            ┌───────────────────────────────────┐
   │  AI ENGINEER                  │            │  FORWARD DEPLOYED ENGINEER (FDE)  │
   │  • designs the machine        │  machine   │  • installs it in each café        │
   │  • makes the coffee better    │ ─────────► │  • connects their water + power    │
   │  • tests: "is it 10% better?" │            │  • adapts it to their menu         │
   │  • picks the best parts       │ ◄───────── │  • fixes problems on site          │
   │                               │  feedback  │  • tells the owner honestly what   │
   │                               │            │    it can and can't do             │
   └───────────────────────────────┘            └───────────────────────────────────┘
```

- The **AI Engineer** works mostly at the factory and makes **the machine itself** good.
- The **FDE** works mostly at the cafés and makes the machine **work for this particular café**, with its own
  water pipes, its own staff, and its own rules. The FDE also brings back what cafés need ("3 cafés asked for
  oat milk") so the factory can improve.

Now replace "coffee machine" with "an AI system" (for example, a question-answering app built on an LLM).

---

## The AI Engineer

**Simple meaning:** builds products and features **on top of AI models**, mostly LLMs. They usually use
existing models (like Claude) instead of creating new ones.

**What they work on:** RAG (letting an LLM answer from your documents, Stage 5), agents (an LLM that can use
tools, Stage 9), prompts, choosing models, and above all **evals**: tests that measure with numbers whether
the system is getting better or worse (Stage 6).

**A normal day (example):**
| Time | What |
|------|------|
| 09:30 | Check last night's test results: answer accuracy dropped from 86% to 81%. Why? |
| 10:00 | Find the cause: a new way of splitting documents cut tables in half. Fix it. |
| 11:30 | Try a cheaper model on 200 test questions. Is it good enough? |
| 14:00 | Team meeting: plan a new "agent" feature. |
| 15:00 | Write code for the feature, then write tests for it. |
| 17:00 | Short write-up: "Cheaper model saves 40% cost, loses 2% accuracy. Recommend: yes for simple questions." |

**Success means:** the system **measurably** works well (accuracy, speed, cost).

---

## The Forward Deployed Engineer (FDE)

**Simple meaning:** an engineer who works **with customers**, inside their world, to make the product
actually work for them. "Forward deployed" comes from the idea of being sent **out to the front line**,
close to the customer. The title was made popular by the company Palantir; today many AI companies hire FDEs.

**What they work on:** connecting the AI system to the customer's data, making it work with how their staff
log in, getting it through the customer's **security review** (their security team checks that it's safe),
fixing problems in the customer's real setup, showing demos, and **being honest about limits**.

**A normal day (example):**
| Time | What |
|------|------|
| 09:00 | Call with a bank's IT team: their staff must log in with their company account (this is called **SSO**, single sign-on: log in once, use many apps). How do we connect to it? |
| 10:30 | Write code to read documents from the bank's file system into the AI system. |
| 12:00 | Bug: answers are slow only at this bank. Cause: their network sends everything through an extra checkpoint (a proxy). Find a fix. |
| 14:00 | Fill in the bank's security questions: "Where does our data go? How long is it kept?" |
| 15:30 | Demo to the bank's managers. One asks: "Will it ever give wrong answers?" Answer honestly, with numbers. |
| 17:00 | Message to the product team: "Three customers need tables in PDFs to work. Can we prioritise it?" |

**Success means:** the **customer gets real value**, safely, in their real environment.

## Where they overlap

```
        AI ENGINEER                         FDE
   ┌──────────────────────┬──────────────────────┐
   │ deep on model quality│ deep on the customer │
   │ evals, tuning        │ login, security,     │
   │ agents, model choice │ networks, data links,│
   │                      │ demos, honest talk   │
   │          ┌───────────┴───────────┐          │
   │          │   BOTH                │          │
   │          │ Python + APIs         │          │
   │          │ building RAG          │          │
   │          │ evals (proving it     │          │
   │          │   works with numbers) │          │
   │          │ debugging             │          │
   │          │ basic deployment      │          │
   │          │ security awareness    │          │
   │          │ clear writing         │          │
   │          └───────────┬───────────┘          │
   └──────────────────────┴──────────────────────┘
```

That's why the first 8 stages of your plan are almost all `[BOTH]`.

## Common confusions

| People think | What's actually true |
|--------------|----------------------|
| "FDE = salesperson" | No. An FDE writes real code and solves real technical problems. They talk to customers a lot, but they're engineers. |
| "FDE = customer support" | No. Support answers tickets. An FDE builds and adapts the system to make it work in the customer's world. |
| "AI Engineer = AI researcher" | No. **Researchers** invent new methods and train big new models. **ML Engineers** train and run custom ML models. **AI Engineers** mostly build products using existing models. The lines blur, but that's the usual split. |
| "The job title tells you everything" | Titles vary a lot. Similar jobs are called *Applied AI Engineer*, *Solutions Engineer*, *Deployment Engineer*, *Customer Engineer*. **Always read the job description, not just the title.** (Your monthly job scan helps here.) |

## 📖 New words
| Word | Meaning in one line |
|------|---------------------|
| AI Engineer | Builds products and features on top of existing AI models. |
| Forward Deployed Engineer (FDE) | An engineer who works with customers to make the product work in their real environment. |
| ML Engineer | Trains, deploys, and maintains custom machine-learning models. |
| AI researcher | Invents new AI methods and trains new models. |
| Evals | Tests that measure an AI system's quality with numbers. |
| Integration | Connecting your system to another system (e.g. the customer's file storage). |
| SSO (single sign-on) | Log in once with your company account and use many apps. |
| Security review | A customer's security team checking that a product is safe before it's allowed in. |
| Proxy | A middle computer that network traffic passes through (common in company networks). |
