# Lesson 0.4a · Your workspace: Python projects, secrets, and git habits

**Stage 0 · The big map** · Time: about 1 hour (read 15 min · try 35 min · explain back 10 min)
*Lesson 0.4 is split in two: **0.4a** (today) sets up your workspace safely; **0.4b** makes your first LLM call.*

## Why this lesson?
Every project from now on runs in this workspace. One habit here matters more than anything else in the
plan: **keeping secrets (like API keys) out of your code and out of git.** A leaked key costs you money.
At a customer it can cost far more, and it's one of the first things a security review checks (Lesson 0.2).

---

## Idea 1: Each project gets its own "toolbox" (virtual environments)
Python projects use **packages** (code other people wrote, like `numpy`). Different projects may need different
**versions** of the same package. If everything shares one big pile, one project's upgrade can break another.

A **virtual environment** is a separate toolbox **per project**: its own Python and its own packages.

```
your computer
 ├── project A  →  .venv/  (numpy 1.26, pandas 2.1)
 └── project B  →  .venv/  (numpy 2.1)        ← no fight between A and B
```

## Idea 2: `uv`: the tool that manages the toolbox
`uv` creates the virtual environment, installs packages, and runs your code inside it. Three commands do most of the work:

| Command | What it does |
|---------|--------------|
| `uv init` | Turns a folder into a Python project (creates `pyproject.toml`) |
| `uv add <package>` | Installs a package into this project's `.venv` and records it |
| `uv run <command>` | Runs a command *inside* this project's toolbox, e.g. `uv run python script.py` |

Two files appear. Here's the difference between them:
| File | Analogy | What it holds |
|------|---------|---------------|
| `pyproject.toml` | Your **shopping list** | "I need python-dotenv" (roughly which packages) |
| `uv.lock` | The **exact receipt** | "python-dotenv **1.2.4**, from here, with this checksum" (exact versions) |

Commit **both** to git. Then anyone (or a fresh cloud machine) gets the *exact same* toolbox with `uv sync`.
**Never commit `.venv/`.** It's big, and it can always be rebuilt from the two files.

## Idea 3: Secrets
An **API key** is a password that lets your code use a paid service (like an LLM API). Anyone who has it can
spend your money.

**The rules:**
1. **Never write a key in your code.** Code gets shared, copied, and pushed.
2. Keep it in an **environment variable**: a named value that lives *outside* your code, which programs can
   read, like `ANTHROPIC_API_KEY`.
3. For local work, environment variables usually come from a **`.env` file** (one `NAME=value` per line).
4. **`.env` must be listed in `.gitignore`**, the file that tells git "never track these."

```
.env          (on your computer only)        your code
┌──────────────────────────┐                ┌─────────────────────────────────┐
│ ANTHROPIC_API_KEY=sk-... │ ──loaded into──►│ key = os.environ["ANTHROPIC_..."] │
└──────────────────────────┘  environment    └─────────────────────────────────┘
      ▲ listed in .gitignore → never pushed
```

**If a key ever gets pushed by mistake:** **revoke it immediately** in the provider's dashboard and create a new one.
Deleting the commit is **not enough**. Bots scan public GitHub for keys constantly, and git history keeps old commits.

## Idea 4: Git habits that save you
- **Look before you commit:** run `git status` and check the list. No `.env`, no `.venv/`?
- **Small commits with clear messages:** `"Add .env loader"`, not `"stuff"`.
- **Commit often.** A commit is a save point you can go back to.

## ✍️ Try it (≈35 min)
Do this in your repo folder on your computer. **Use a fake secret today.** Your real API key comes in 0.4b.

### Step 1: Make the repo a Python project (5 min)
1. Install uv if you don't have it (see the official uv installation instructions for your OS), then check it with `uv --version`.
2. In the repo root, run:
   ```
   uv init --no-readme --python 3.12
   ```
   (`--no-readme` keeps your existing README.) Delete the `main.py` it creates; you don't need it.
3. Create a file called `.gitignore` in the repo root containing:
   ```
   .venv/
   .env
   __pycache__/
   ```
4. Run `git status`. You should see `pyproject.toml`, `.python-version`, and `.gitignore` as new files.

### Step 2: ① From scratch: read `.env` yourself (15 min)
1. Create `.env` in the repo root with one **fake** secret:
   ```
   DEMO_SECRET="hello123" # this is a comment
   ```
2. Write `experiments/00a_read_env.py` that:
   - opens `.env` and goes through it line by line,
   - skips empty lines and lines starting with `#`,
   - splits each line into a name and a value at the **first** `=`,
   - puts it into `os.environ`,
   - then prints the secret **masked**: only the first 3 characters + `***`.
3. Run it: `uv run python experiments/00a_read_env.py`
4. **Look closely at what it prints.** Is the value `hello123`? Or did the quotes and the comment sneak in?

### Step 3: ② With a package: `python-dotenv` (10 min)
1. `uv add python-dotenv`
2. Write `experiments/00a_read_env_dotenv.py` that calls `load_dotenv()` and prints the same masked value.
3. Compare the two outputs.

### Step 4: Compare and commit (5 min)
1. Create `experiments/NOTES.md` with a **Compare** section (3 lines): what `python-dotenv` handled that yours
   didn't, what it hid from you, and which you'd use at work.
2. `git status`. **Make sure `.env` and `.venv/` are NOT listed.** Then commit and push.

<details>
<summary>Stuck? Hints and a reference solution (only after you've tried!)</summary>

**Hints for Step 2:** `line.strip()` removes spaces and newlines · `line.startswith("#")` · `line.split("=", 1)`
splits at the first `=` only · `os.environ[name] = value`.

**Reference (one possible solution):**
```python
import os

with open(".env") as f:
    for line in f:
        line = line.strip()
        if not line or line.startswith("#"):
            continue
        name, value = line.split("=", 1)
        os.environ[name.strip()] = value.strip()

secret = os.environ["DEMO_SECRET"]
print(secret[:3] + "***")
```

**What you should notice:** this simple version stores the value as `"hello123" # this is a comment`, so the
masked output starts with `"he`. `python-dotenv` gives you `hello123`: it removes the quotes and the comment.
It also handles `export NAME=...`, multi-line values, and by default it **doesn't overwrite** an environment
variable that's already set. Writing your own showed you all the cases it quietly handles.
</details>
