A **"find similar messages"** tool: type any message, and it finds the 3 most similar messages out of the 5,574,
**without using any labels**. That's your first step into **unsupervised learning**. The same idea, with better

## The kinds of learning (the short version)
| Kind | Learns from | Example | You'll build it in |
|------|-------------|---------|--------------------|
| **Supervised** | Examples **with** labels (right answers) | Your spam stump | 1.2 ✅ |
| **Unsupervised** | Examples **without** labels; finds similarity and groups | Similar messages, k-means clusters | **1.3a, 1.3b** |
| **Self-supervised** | Raw data where the "label" is hidden *in* the data itself (e.g. the next word) | How LLMs like Claude are trained | Stage 2 |
| **Reinforcement** | Trying actions and getting rewards or penalties | Game-playing AI; tuning LLMs with human feedback | Stage 2 (concept) |

## The only new theory: distance
Each message is a list of numbers (its features), so you can measure **how far apart** two messages are.
With just 2 features it's ordinary distance on a map:
```
digits ▲
    12 │            ● spam A (length 100, digits 12)
       │
     0 │  ● ham B (length 20, digits 0)
       └──────────────────────────────► length
          distance(A, B) = √((100−20)² + (12−0)²) = √(6400 + 144) ≈ 80.9
```
With 7 features it's the same formula, just with 7 terms. This is called **Euclidean distance**.
**Small distance = similar messages.**

```python
print(names)
print(texts[0][:60], vectors[0])
```
- A list of numbers that describes something is called a **vector**. Your `X` in Lesson 1.2 was a list of vectors.
- **Run it.** Each message is now 7 numbers.

### Step 2: A distance function
```python
def distance(a, b):
    return math.sqrt(sum((x - y) ** 2 for x, y in zip(a, b)))

print(distance([100, 12], [20, 0]))            # the map example above: should print about 80.9
```
- `zip(a, b)` pairs up the features: (length A, length B), (digits A, digits B), …
- `(x - y) ** 2` squares each difference (always positive), `sum` adds them, and `math.sqrt` takes the square root.
- **Run it** and check you get about 80.9. Then delete the test `print`.

### Step 3: Find the nearest messages
```python
def nearest(query_vector, vecs, k=3):
    order = sorted(range(len(vecs)), key=lambda i: distance(query_vector, vecs[i]))
    return order[:k]                           # the positions of the k closest messages
```
- `range(len(vecs))` = the positions 0, 1, 2, … 5573.
- `sorted(..., key=...)` sorts those positions **by their distance to the query**, closest first.
- `lambda i: ...` is a tiny one-line function: "for position `i`, the sort value is this distance".

| Position `i` | `vecs[i]` | distance to query |
|---|---|---:|
| 0 | [100, 12] | 10.0 |

| 2 | [95, 10] | **5.1** |
| 3 | [30, 1] | 60.8 |

`range(4)` → 0, 1, 2, 3 → sorted by distance → `[2, 0, 3, 1]` → `order[:2]` → **`[2, 0]`**.

- `sorted(items, key=f)` = sort the items, comparing them by `f(item)`. E.g. `sorted(["banana", "kiwi", "apple"], key=len)` → `['kiwi', 'apple', 'banana']`.
- `lambda i: distance(query_vector, vecs[i])` is the same as `def distance_of_position(i): return distance(query_vector, vecs[i])`.
- We sort **positions**, not vectors, so we can later look up `texts[i]` and `labels[i]`.

The same function, the long way:
```python
def nearest(query_vector, vecs, k=3):
    pairs = []
    for i in range(len(vecs)):
        d = distance(query_vector, vecs[i])
        pairs.append((d, i))          # (distance, position)
    pairs.sort()                      # smallest distance first
    return [i for d, i in pairs[:k]]  # positions of the k closest
```

### Step 4: Try it, and look closely
```python
queries = [
    "WINNER!! Call 09061701461 now to claim your FREE prize www.win.com",
    "ok see you soon",
]
for q in queries:
    qv = [features(q)[n] for n in names]
    print("\nQUERY:", q)
    for i in nearest(qv, vectors):
        print(f"  {labels[i]:<5} d={distance(qv, vectors[i]):6.1f}  {texts[i][:70]}")
```
**Run it.** The neighbours of the WINNER message are spam, but **read them**: do they have "FREE", "WIN", a link?
Mostly they just have a **similar length**. Why?
- `length` goes up to **910**, `digits` up to 47, and `has_free` is only 0 or 1.
- A length difference of 50 adds 2,500 to the sum. A `has_free` difference adds at most **1**.
- So **length drowns out everything else.** The search is really "find messages of similar length".

### Step 5: Fix it with scaling
**Scaling** (here **min-max scaling**) squeezes every feature into the range **0 to 1**, so each one counts about the same:
`scaled = (value − smallest) / (largest − smallest)`
```python
mins = [min(col) for col in zip(*vectors)]     # smallest value of each feature, over all messages
maxs = [max(col) for col in zip(*vectors)]     # largest value of each feature
print("mins", mins)
print("maxs", maxs)

def scale(v):
    return [(x - lo) / (hi - lo) if hi > lo else 0.0 for x, lo, hi in zip(v, mins, maxs)]

scaled = [scale(v) for v in vectors]
```
- `zip(*vectors)` **flips the table**: instead of one row per message, you get one column per feature. That's handy for min/max.
- `if hi > lo else 0.0` avoids dividing by zero if a feature never changes.

Now run the queries again on the scaled vectors. **The query must be scaled with the same `mins`/`maxs`:**
```python
for q in queries:
    qv = scale([features(q)[n] for n in names])   # same scaling as the data!
    print("\nQUERY:", q)
    for i in nearest(qv, scaled):
        print(f"  {labels[i]:<5} d={distance(qv, scaled[i]):6.3f}  {texts[i][:70]}")
```
**Run it.** Now the WINNER message's neighbours share **FREE** and **WIN**, so they're really similar.
> Remember the `>=` vs `>` bug from 1.2? Same lesson here: whatever you did to the data (scaling with these
> `mins`/`maxs`), you must do **exactly the same** to every new message.

## ② The package version: scikit-learn (≈15 min)
Create `projects/classifier/sk_similar.py`:
```python
from sklearn.neighbors import NearestNeighbors
from sklearn.preprocessing import MinMaxScaler

from sms_data import features, load_sms

labels, texts = load_sms()
names = list(features("x"))                    # feature names (any text works to get the keys)
X = [[features(t)[n] for n in names] for t in texts]

scaler = MinMaxScaler()                        # the same min-max scaling you wrote
X_scaled = scaler.fit_transform(X)             # fit = learn mins/maxs, transform = apply them
nn = NearestNeighbors(n_neighbors=3).fit(X_scaled)   # stores the vectors for fast searching

queries = ["WINNER!! Call 09061701461 now to claim your FREE prize www.win.com", "ok see you soon", ""]
q_scaled = scaler.transform([[features(q)[n] for n in names] for q in queries])   # transform ONLY: reuse the same mins/maxs
distances, indices = nn.kneighbors(q_scaled)
for q, ds, ids in zip(queries, distances, indices):
    print("\nQUERY:", repr(q))
    for d, i in zip(ds, ids):
        print(f"  {labels[i]:<5} d={d:.3f}  {texts[i][:70]}")
print("\nscaler min:", scaler.data_min_)
print("scaler max:", scaler.data_max_)
```
- **`fit_transform`** on the data learns the mins/maxs and scales the data. On new messages, use **`transform` only**, so
  you reuse the same mins/maxs. Calling `fit` again on new data would be the scaling version of your `>=`/`>` bug.
- **`NearestNeighbors`** does your `nearest()` search, but with clever tricks to stay fast on millions of items.

## 📌 Key takeaways
- **Unsupervised:** no labels needed. You can still find **similar** items by measuring **distance** between feature vectors.
- **Euclidean distance** = √(sum of squared differences). Small = similar.
- **Features with big ranges drown out small ones.** **Scaling** (e.g. min-max to 0–1) makes them count fairly.
- **Scale new data with the numbers learned from the training data** (`transform`, not `fit`). New values can land outside 0–1.
- This "nearest neighbours" search is the core idea behind "similar items" and the search inside RAG. Later you'll swap
  these 7 hand-made features for **embeddings**, which capture meaning.

## 📖 New words
| Word | Meaning in one line |
|------|---------------------|
| Unsupervised learning | Learning from data **without** labels (similarity, groups). |
| Self-supervised learning | The "label" comes from the data itself (e.g. the next word); how LLMs are trained. |
| Reinforcement learning | Learning by trying actions and getting rewards. |
| Vector | A list of numbers describing one item. |
| Euclidean distance | Straight-line distance between two vectors. |
| Nearest neighbours | The items closest to a query (smallest distance). |
| Scaling (min-max) | Rescaling each feature to 0–1 so all features count fairly. |
| `fit` / `transform` | Learn the numbers (e.g. mins/maxs) / apply them. |
